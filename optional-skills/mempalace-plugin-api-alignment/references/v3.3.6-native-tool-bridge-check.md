## Important lessons

1. Treat MemPalace library/API alignment and palace-store health as separate problems.
   - The provider/tool bridge can be correct while the configured palace path is corrupt.
   - Validate the bridge against a known-good palace path before blaming the provider.

2. `hermes mcp test mempalace` and provider-native tool dispatch are separate checks.
   - MCP health proves transport/server discovery.
   - `load_memory_provider("mempalace")`, `get_tool_schemas()`, and a real `handle_tool_call()` smoke prove Hermes-native integration.

3. Keep the provider fail-open.
   - `get_tool_schemas()` should return `[]` if native API import/setup fails.
   - `handle_tool_call()` should catch exceptions and return JSON error strings rather than crashing Hermes.

4. Verify against the real tool count.
   - Use `native_tool_count` in diagnostics.
   - Assert the expected count in smoke scripts and contract tests.

## Pitfall

Do not conclude "the plugin is broken" merely because the default palace path errors out. If the configured palace data store is corrupt, re-run the native tool smoke against a known-good backup path to separate storage corruption from API/provider drift.
